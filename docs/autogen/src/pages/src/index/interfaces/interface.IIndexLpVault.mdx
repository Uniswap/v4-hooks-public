# IIndexLpVault

[Git Source](https://github.com/Uniswap/v4-hooks-public/blob/5695a6964b93f4313077d695f6d6c584fbab25a4/src/index/interfaces/IIndexLpVault.sol)

**Title:** IIndexLpVault

A passive index of `stock / index token` Uniswap v4 pools: one PositionManager position per pool, deposits routed
toward target weights, proportional redemptions. Shares are the vault's own ERC-20.

<i>

Every amount is in token wei; every value (`nav`, `indexValue`, `valueInIndex`) is in index-token wei.

</i>

<a id="deposit-uint256-uint256-uint256-address"></a>

### deposit

Adds `stockAmounts[i]` and `indexAmounts[i]` to constituent i's position (minting it on first use), returns
what the positions did not take to the caller and mints shares for the value added to `to`. Shares are
priced with each pool's current composition valued at the hook's reference price, and the deposit
reverts `PriceDeviation` while any pool is off its reference by more than `maxDeviationBps`.

```solidity
function deposit(uint256[] calldata stockAmounts, uint256[] calldata indexAmounts, uint256 minShares, address to)
        external
        returns (uint256 shares);
```

## Errors

### LengthMismatch

An amounts array does not have one entry per constituent

```solidity
error LengthMismatch();
```

### SlippageExceeded

Fewer shares minted than `minShares`, or less of a token paid out than its redeem minimum

```solidity
error SlippageExceeded();
```

### DepositsArePaused

Deposits are paused by the owner (redemptions never are)

```solidity
error DepositsArePaused();
```

### ZeroShares

The deposit would mint, or the redemption burns, zero shares

```solidity
error ZeroShares();
```

### PriceDeviation

Constituent i's pool price is more than `maxDeviationBps` away from its hook reference price

