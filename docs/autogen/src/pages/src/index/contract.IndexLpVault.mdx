# IndexLpVault

[Git Source](https://github.com/Uniswap/v4-hooks-public/blob/5695a6964b93f4313077d695f6d6c584fbab25a4/src/index/IndexLpVault.sol)

**Inherits:** [IIndexLpVault](/src/index/interfaces/interface.IIndexLpVault), ERC20, Ownable, ReentrancyGuardTransient

**Title:** IndexLpVault

Holds one v4 PositionManager position per `stock / index token` pool and issues itself as the share token.
Deposits bring both tokens of every pool (`previewDeposit` routes value toward the target weights), mint or
increase the positions in one `modifyLiquidities` call and return whatever the positions did not take.
Redemptions pay the same fraction of every position and idle balance and are never paused.

<i>

Deposits price shares with each pool's current composition valued at the hook's keeper reference price, and
revert while a pool's price is off that reference by more than `maxDeviationBps`: pushing a pool's price moves
only the composition. Redemptions pay in kind; the views value at spot.

</i>

<a id="deposit-uint256-uint256-uint256-address"></a>

### deposit

Adds `stockAmounts[i]` and `indexAmounts[i]` to constituent i's position (minting it on first use), returns
what the positions did not take to the caller and mints shares for the value added to `to`. Shares are
priced with each pool's current composition valued at the hook's reference price, and the deposit
reverts `PriceDeviation` while any pool is off its reference by more than `maxDeviationBps`.

<i>

Fees are collected first so the deposit is priced against a NAV that includes them. The tokens a position
does not take stay in the vault after the PositionManager's Permit2 pulls, so they are refunded from here
(a PositionManager SWEEP would find nothing to sweep). The event carries the spot NAV, as `nav()` reports.

</i>

```solidity
function deposit(uint256[] calldata stockAmounts, uint256[] calldata indexAmounts, uint256 minShares, address to)
        external
        nonReentrant
        returns (uint256 shares);
```
