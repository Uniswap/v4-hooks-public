# StableFeeCalculation

[Git Source](https://github.com/Uniswap/v4-hooks-public/blob/3d5b2620fe2b9ba7f01645160e1b841cf585c425/src/stable/libraries/StableFeeCalculation.sol)

**Title:** StableFeeCalculation

Library providing core mathematical functions for calculating dynamic swap fees

## Constants

### ONE_E6

Scalar for pips precision (1e6 = 100%)

```solidity
uint256 internal constant ONE_E6 = 1e6;
```

### ONE_E12

Scalar for scaled precision (1e12 = 100%)

```solidity
uint256 internal constant ONE_E12 = 1e12;
```

### UNDEFINED_DECAYING_FEE_E12

Sentinel: no decaying fee (inside optimal range).

```solidity
uint256 internal constant UNDEFINED_DECAYING_FEE_E12 = 1e12 + 1;
```

### MAX_FEE_E6

Maximum LP fee toFeeE6 returns. Pool.swap compounds the LP fee with the directional
protocol fee (protocol taken from the input first, LP fee on the remainder) and
rounds the result UP to a whole pip, so an LP fee of 999_999 compounds to exactly
1e6 (100%) for ANY nonzero protocol fee; 999_998 compounds to at most 999_999 for
all protocol fees up to ProtocolFeeLibrary.MAX_PROTOCOL_FEE
(= LPFeeLibrary.MAX_LP_FEE - 2).

```solidity
uint256 internal constant MAX_FEE_E6 = 1e6 - 2;
```

### Q48

Scale used to preserve precision in sqrt ratio math.

```solidity
uint256 internal constant Q48 = 2 ** 48;
```

## Functions

<a id="tofeee6-uint256"></a>

### toFeeE6

Convert a fee from 1e12 precision to the uint24 E6 (pips) precision v4 charges

<i>

Rounds up, so a nonzero fee never rounds down to a lower pip: a fee below 1 pip
charges 1 pip instead of becoming an explicit 0-fee override. A fee of exactly zero
still converts to zero.

</i>

```solidity
function toFeeE6(uint256 feeE12) internal pure returns (uint24);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| feeE12 | `uint256` | The fee in 1e12 precision |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| &lt;none&gt; | `uint24` | The fee in E6 precision, rounded up and clamped to MAX_FEE_E6 so the fee v4 actually<br/>charges (LP fee compounded with the protocol fee) stays strictly below 100%. At a<br/>charged fee of exactly 1e6, exact-output swaps revert and exact-input swaps consume<br/>the whole input as fee, so no swap can move the price through active liquidity —<br/>leaving no way to move a saturated pool back toward reference. The clamp keeps<br/>exact-output swaps available and lets exact-input swaps large enough to leave a<br/>nonzero post-fee remainder move the price. |

<a id="derivelogk-uint256"></a>

### deriveLogK

Derive the quantized log-space decay rate the slow path exponentiates with

<i>

logK = ceil(-lnWad(k as wad) / 2^24). Rounding UP keeps the reconstructed exponent
(logK &lt;&lt; 24) at least as large as the computed -ln(k), so the slow-path decay factor
never exceeds the exact k^n — the fee never decays slower than configured and stays
monotone across the blocksPassed 4 -> 5 switch from exact k^n multiplication (fast
path) to the approximate exp(-logK * n) formula (slow path). Since the uint24 type
caps k below Q24 1.0 (2^24), -ln(k) > 0 always and ceil rounding keeps the result
nonzero — so logK = 0 (which would disable decay entirely) is unreachable.

</i>

```solidity
function deriveLogK(uint256 k) internal pure returns (uint256 logK);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| k | `uint256` | The decay factor per block in Q24 format; must be nonzero (validated at config time) |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| logK | `uint256` | The derived value |
